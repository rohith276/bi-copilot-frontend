Grounded SQLite AST 安全な自然言語SQL

Injects column schemas and date bounds. Disallows dangerous DDL/DML statements. Executes in 3.5ms in memory. 実際の項目名と日付をAIに教えてSQLを作成。データを消す命令をブロックし、3.5ミリ秒で集計します。

2. TIME SERIES FORECAST

Holt-Winters Tournament 売上の波を捉える予測

Auto-aggregates daily gaps to weekly cadence. 86.3% holdout test confidence with 80% & 95% upper/lower bounds. 注文のない日があっても予測が潰れない工夫を搭載。86.3%の信頼度で予測の上振れ・下振れ幅を表示します。

3. AUTOML REGRESSION

4-Model Competition AIモデルの自動コンテスト

Trains Linear, Ridge, Lasso, and Random Forest on 80/20 holdout. Champion RF model achieved test R² = 0.5218. 4つのAIモデルを競わせ、一番良いモデルを自動選定。何が売上に影響しているかをハッキリ数字で示します。

4. ANOMALY DETECTION

Tri-Layer Outlier Detection データの異常をすぐに見つける

Combines Median Absolute Deviation (MAD), Tukey IQR fences, and Isolation Forest. Flagged 134 extreme outliers in 9,994 orders. 飛び抜けて高い売上や、赤字なのに注文が多い矛盾データを自動発見。約1万件のデータから134件の異常を検知しました。

5. ROOT-CAUSE DECOMPOSITION

100% Mathematical Conservation 原因分析 (100%の計算一致)

Sum of parts matches the total +$85,617.60 change. Decomposes into Volume effect (+$68,193) vs Ticket Rate effect (+$17,424). 内訳の合計が全体の増減額と100%ピッタリ一致。「客数が増えた分」と「単価が上がった分」に分けて原因を教えます。

Engineering Proof • Slide 09 技術の信頼性 • スライド 09

Production Engineering Hurdles Solved 開発で解決した重要な技術的課題

How we overcame edge-cases that break ordinary AI wrappers ふつうのAIアプリが失敗しがちな落とし穴を、技術の工夫で解決しました

Hardened Architecture 堅牢な設計
1. PREVENTING SQL HALLUCINATIONS

Schema Grounding & In-Memory Dry-Runs AIがウソのカラム名を作るのを防ぐ

Challenge: Ambiguous questions make AI fabricate non-existent columns.
Solution: We dynamically inject exact DDL schemas and date bounds, and test-run queries in RAM before returning results to the user. 課題: 曖昧な質問に対して、AIが存在しない項目名を勝手に作ってエラーになる。
解決策: 実際のテーブル構造をAIに事前に教え、さらに画面に出す前にテスト実行して合格したSQLだけを返します。

2. PREVENTING FLAT-LINE FORECASTS

Adaptive Weekly Cadence Aggregation 取引のない日で予測線が潰れるのを防ぐ

Challenge: Daily zero-fills on weekends caused forecast lines to collapse into flat zeroes.
Solution: When empty gaps exceed 40%, the algorithm automatically rolls up data to Weekly cadence, preserving true growth trends. 課題: 注文のない日をゼロで埋めると、AI予測がゼロに引っ張られて真っ平らになる。
解決策: ゼロが多いデータは自動的に「週単位」にまとめて計算し、きれいな右肩上がりのトレンドを維持します。

3. FIXING WORKSPACE STATE LOSS

Coordinated LocalStorage Persistence タブ移動でグラフ設定が消えるのを防ぐ

Challenge: Navigating between tabs erased user-selected chart axes.
Solution: Lifted state into a persistent React context synced with `localStorage`, so users can switch tabs with zero loss. 課題: グラフ作成中に別のタブを見ると、選んでいた項目がリセットされてしまう。
解決策: 状態をブラウザの保存領域（localStorage）と自動同期させ、タブを行き来しても作業が消えないようにしました。

4. STOPPING ONE-HOT MEMORY EXPLOSIONS

High-Cardinality Guardrails 項目が多すぎてパソコンが固まるのを防ぐ

Challenge: Columns with thousands of customer IDs crashed machine learning memory.
Solution: Enforced a threshold: only top 10 categories are one-hot encoded; the long tail is grouped into `__Other__`. 課題: 顧客IDなど何千種類もある項目を学習させると、データ量が爆発してサーバーが止まる。
解決策: よく出る上位10個だけを残し、その他は「その他」にまとめることで、メモリを守り高速化しました。
